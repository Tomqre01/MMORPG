# แผนพัฒนาเกมมือถือ MMORPG แนว MU Origin

> ร่างแรก 16 ต.ค. 2026 · ใช้เป็นจุดตั้งต้นสำหรับคุยกัน ยังไม่ได้ล็อกขอบเขต

## 1. เกมแนว MU Origin มีอะไรบ้าง

MU Origin เป็น MMORPG มือถือแนวนอน มุมกล้องเอียง (isometric / 3D มุมสูง) เน้นออโต้เพลย์ ตีมอนฟาร์มของ อัปพลังตัวละครเป็นตัวเลข แล้วแข่งกันใน PvP และกิจกรรมกิลด์ จุดสำคัญคือ "ระบบเติบโต" หลายชั้นที่ผู้เล่นอัปได้ทุกวัน

**ระบบหลัก (Core)**
- คลาสตัวละคร 3 คลาสเริ่มต้น (เช่น นักดาบ / นักเวท / ธนู) พร้อมสกิลแอคทีฟและพาสซีฟ
- เลเวลและการรีเซ็ต/จุติ (Rebirth) เพื่อปลดล็อกขั้นถัดไป
- ต่อสู้แบบเรียลไทม์ + **Auto-battle / Auto-quest** (สำคัญมากสำหรับมือถือ)
- แผนที่เปิดหลายโซน มอนสเตอร์ บอสฟิลด์ที่เกิดตามเวลา

**ระบบเติบโต (Progression)**
- ไอเทมและอุปกรณ์: ตีบวก (+1 ถึง +15), เพิ่มออปชัน, ประกอบเซ็ต, อัญมณี
- ปีก (Wings), สัตว์ขี่ (Mount), สัตว์เลี้ยง (Pet) ที่อัปเกรดได้
- ค่าพลังรวม (Combat Power) เป็นตัวเลขเดียวที่ผู้เล่นใช้เทียบกัน

**เนื้อหาและกิจกรรม**
- ดันเจี้ยนรายวัน, Boss Raid, หอคอยไต่ชั้น
- อีเวนต์ตามเวลา (เช่น Blood Castle, Devil Square ในต้นฉบับ)
- เควสต์หลัก เควสต์รายวัน และระบบภารกิจสะสมแต้ม

**สังคมและ PvP**
- ปาร์ตี้, กิลด์, แชตโลก/กิลด์/ส่วนตัว
- อารีน่า 1v1 จัดอันดับ, ศึกกิลด์ชิงปราสาท
- ตลาดซื้อขายระหว่างผู้เล่น (Auction House)

**ระบบรายได้ (Monetization)**
- เพชร/สกุลเงินพรีเมียม, VIP level, Battle Pass, แพ็กเติมเงินครั้งแรก
- กาชาชิ้นส่วนปีก/สัตว์เลี้ยง (ต้องระวังกฎหมายกาชาในแต่ละประเทศ)

> หมายเหตุ: ชื่อ "MU", ตัวละคร, ภาพ และชื่ออีเวนต์เป็นทรัพย์สินของ Webzen ควรทำ "แนวเดียวกัน" แต่ใช้โลก ชื่อ และงานศิลป์ของเราเอง

## 2. เทคโนโลยีที่แนะนำ

| ส่วน | ตัวเลือกแนะนำ | เหตุผล |
|---|---|---|
| Game client | **Unity (C#)** | เกม MMO มือถือส่วนใหญ่ในเอเชียใช้ Unity, ทรัพยากรและ asset store เยอะ, build Android/iOS ได้ดี |
| ทางเลือก client | Godot 4 | ฟรีทั้งหมด เบา แต่ระบบนิเวศสำหรับ 3D มือถือยังน้อยกว่า |
| Game server | **Go** หรือ **C# (.NET)** | รองรับผู้เล่นพร้อมกันจำนวนมาก, C# แชร์โค้ด/โมเดลข้อมูลกับ Unity ได้ |
| เฟรมเวิร์กเซิร์ฟเวอร์ (ทางลัด) | Nakama (open source) | มีบัญชีผู้ใช้ แชต กิลด์ ลีดเดอร์บอร์ด สำเร็จรูป ลดเวลาทำระบบพื้นฐาน |
| โปรโตคอล | TCP/WebSocket + Protobuf | ข้อความเล็ก เร็ว, เหมาะกับเกมที่ตรวจผลบนเซิร์ฟเวอร์ |
| ฐานข้อมูล | PostgreSQL + Redis | Postgres เก็บข้อมูลถาวร, Redis เก็บสถานะออนไลน์ อันดับ และแคช |
| ข้อมูลเกม (config) | Google Sheets/Excel → export เป็น JSON | นักออกแบบปรับค่าสมดุลได้โดยไม่ต้องแก้โค้ด |
| โฮสติ้ง | Docker บน VPS/Cloud (เริ่มเล็ก) | ขยายเป็นหลายเซิร์ฟเวอร์ (shard) ภายหลัง |

**หลักสถาปัตยกรรมสำคัญ:** เซิร์ฟเวอร์เป็นผู้ตัดสินทุกอย่าง (server-authoritative) ทั้งดาเมจ ดรอป และการตีบวก เพื่อกันโกง ส่วน client แสดงผลอย่างเดียว

```
[Unity Client] ⇄ Gateway ⇄ Game Server (แผนที่/การต่อสู้)
                          ⇄ Social Service (แชต/กิลด์/ตลาด)
                          ⇄ PostgreSQL + Redis
```

## 3. โรดแมปแบบแบ่งเฟส

เริ่มจากของเล็กที่เล่นได้จริงก่อน แล้วค่อยขยาย ไม่ควรเริ่มด้วยการทำทุกระบบพร้อมกัน

**เฟส 0: เตรียมงาน**
- เขียน Game Design Document ฉบับย่อ (โลก คลาส ลูปการเล่น)
- เลือก art style และหา asset ชั่วคราว (asset store / ฟรี)
- ตั้ง repository, โครง Unity project, โครงเซิร์ฟเวอร์

**เฟส 1: ต้นแบบเล่นคนเดียว (Offline Prototype)**
- ตัวละคร 1 คลาส เดินด้วย virtual joystick ในแผนที่ 1 แผนที่
- ตีมอน 2–3 ชนิด, สกิล 3 ปุ่ม, ปุ่ม Auto-battle
- ดรอปไอเทม, กระเป๋า, สวมอุปกรณ์, ตีบวกพื้นฐาน, เลเวลอัป
- เป้าหมาย: ตอบให้ได้ว่า "ตีมอนแล้วสนุกไหม รู้สึกอยากอัปไหม"

**เฟส 2: ออนไลน์พื้นฐาน (Vertical Slice)**
- ล็อกอิน สร้างตัวละคร บันทึกข้อมูลบนเซิร์ฟเวอร์
- เห็นผู้เล่นอื่นในแผนที่เดียวกัน, แชตโลก
- ย้ายการคำนวณต่อสู้และดรอปไปไว้ที่เซิร์ฟเวอร์
- ปาร์ตี้ และดันเจี้ยน 1 ด่าน

**เฟส 3: ระบบเติบโตและสังคม**
- เพิ่มเป็น 3 คลาส, ปีก, สัตว์เลี้ยง, ระบบ Combat Power
- กิลด์, อารีน่า 1v1, เควสต์รายวัน, บอสฟิลด์
- ระบบอีเวนต์ตามเวลา

**เฟส 4: พร้อมเปิดทดสอบ (Closed Beta)**
- ระบบร้านค้าและการชำระเงิน (Google Play / App Store)
- ตลาดซื้อขาย, ศึกกิลด์
- ระบบกันโกง, log, เครื่องมือแอดมิน (GM tools)
- ทดสอบโหลด, ปรับสมดุล, เปิด Closed Beta

**เฟส 5: Soft Launch และ Live Ops**
- เปิดในบางประเทศก่อน วัดค่า retention และรายได้
- อัปเดตคอนเทนต์ตามรอบ, อีเวนต์, ซีซัน

## 4. ความเสี่ยงที่ควรรู้ตั้งแต่ต้น
- **ขอบเขตใหญ่มาก:** MMORPG เชิงพาณิชย์ปกติใช้ทีมหลายสิบคน ทีมเล็กควรตั้งเป้าที่ต้นแบบและ vertical slice ก่อน
- **งานศิลป์ 3D** เป็นต้นทุนใหญ่ที่สุด ควรตัดสินใจ art style ให้เร็ว (3D low-poly ประหยัดกว่า realistic มาก)
- **ค่าเซิร์ฟเวอร์และการดูแล** หลังเปิดเกมต้องมีคนดูแลตลอด
- **ลิขสิทธิ์:** ห้ามใช้ชื่อ ภาพ หรือโมเดลจาก MU โดยตรง
- **กฎหมายกาชา/ความน่าจะเป็น** ต้องเปิดเผยอัตราดรอปในหลายประเทศ

## 5. ขั้นถัดไปที่เสนอ
1. ยืนยันขนาดทีม ประสบการณ์ และแพลตฟอร์มเป้าหมาย
2. เลือก engine (แนะนำ Unity) และ art style
3. เริ่มเฟส 1: สร้าง repository และต้นแบบตีมอนคนเดียว
